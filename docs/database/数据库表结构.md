# 一棵树 (OneTree) 数据库表结构

一棵树系统的后端采用 PostgreSQL 作为存储介质，数据表通过 **SQLModel**（结合 Pydantic 与 SQLAlchemy）进行声明式定义。

## 技术说明
* **ORM 框架**：SQLModel（当前共 20 张数据表：11 张核心学习与会话表 + 9 张教材知识库与后台任务表）
* **JSON 支持**：使用 PostgreSQL `JSONB` 格式存储画像、路径、课程大纲等结构化数据。
* **时区规范**：所有 `created_at`、`updated_at`、`published_at` 等时间字段，均使用 UTC 时间。
* **迁移管理**：生产环境使用 `backend/migrations/versions/`（当前至 `0005_quiz_submission_recovery`）。

## 关系总览

```text
user (uid PK)
 ├── 1:1 ── userprofile (user_uid PK/FK)
 ├── 1:N ── conversationsession (session_id PK, user_uid FK)
 ├── 1:N ── cultivationprogram (program_id PK, teacher_uid FK)
 ├── 1:N ── useryearlearningpath (user_uid PK/FK, grade_year PK)
 ├── 1:N ── usercourseknowledgeoutline (user_uid PK/FK, course_id PK)
 ├── 1:N ── chapterprogress (user_uid PK/FK, course_node_id PK, chapter_id PK)
 ├── 1:N ── chapterweakness (weakness_id PK, user_uid FK)
 ├── 1:N ── courseresourcequality (user_uid PK/FK, course_node_id PK)
 └── 1:N ── chapterquiz (quiz_id PK, user_uid FK)
              └── 1:N ── chapterquizattempt (attempt_id PK, quiz_id FK, user_uid FK)

教材知识库与后台任务表（逻辑关联，无数据库外键）：
knowledgesource ─▶ textbook ─▶ textbooksectioncontent / textbookextensionresource
knowledgegap ─▶ knowledgegapfollow / knowledgegapnotice
knowledgebaseingestionjob / workerheartbeat
```

## 1. user（用户表）

存储系统内所有的学生与管理员账号信息。

| 字段 | 类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |
| `uid` | str | PK | 用户唯一标识 (UUID 字符串) |
| `username` | str | NOT NULL, 1-64 字符, 索引 | 用户名/显示名 |
| `identifier` | str | NOT NULL, 3-128 字符, 唯一索引 | 登录标识（邮箱或 11 位中国大陆手机号，或第三方登录 ID） |
| `role` | str | 默认 "student", 索引, 最大长 16 | 角色：`student` / `admin`（历史 `teacher` 角色已合并迁移为 `admin`） |
| `school` | str | 默认 "", 索引, 最大长 128 | 学校名称 |
| `major` | str | 默认 "", 索引, 最大长 128 | 所属专业 |
| `class_name` | str | 默认 "", 索引, 最大长 128 | 班级名称 |
| `provider` | str | 默认 "password", 索引, 最大长 32 | 认证方式：`password` / `qq` / `xuexitong` |
| `password_hash`| str | 可空, 最大长 128 | 密码哈希（provider 为 password 时必填） |
| `is_active` | bool | 默认 True | 账户是否处于激活状态 |
| `created_at` | datetime| UTC, 默认当前时间 | 账号注册创建时间 |
| `updated_at` | datetime| UTC, 默认当前时间 | 信息更新时间 |
| `last_login_at`| datetime| 可空 | 最后一次成功登录的时间 |

## 2. cultivationprogram（人培方案表）

由管理员发布，供某个特定班级/专业匹配的通用学习大纲模板。

| 字段 | 类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |
| `program_id` | str | PK, 最大长 64 | 培养方案唯一标识 |
| `teacher_uid` | str | FK ➡️ `user.uid`, 索引 | 发布该培养方案的管理员用户 ID（历史字段名保留为 `teacher_uid`） |
| `school` | str | NOT NULL, 联合唯一, 索引, 最大 128 | 关联的学校 |
| `major` | str | NOT NULL, 联合唯一, 索引, 最大 128 | 关联的专业 |
| `class_name` | str | NOT NULL, 联合唯一, 索引, 最大 128 | 关联的班级 |
| `courses` | JSON | 默认 [] | 包含的课程大纲节点列表 |
| `published_at` | datetime| 可空 | 方案发布时间 (为 null 表示草稿状态) |
| `created_at` | datetime| UTC | 创建时间 |
| `updated_at` | datetime| UTC | 更新时间 |

* **唯一约束**：`school + major + class_name` 建立联合唯一约束。每个班级只能拥有一套有效的培养方案。

| 字段 | 类型 | 约束 | 说明 |

| `outline_data` | JSON | 默认 {} | 大纲结构数据（章节列表、章节要点、视频/动画关联等） |

## 6. chapterquiz（章节测验表）

自测森林阶段的数据，记录为特定章节动态生成的测验题集。

| 字段 | 类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |
| `quiz_id` | str | PK, 最大长 64 | 测验唯一 ID |
| `user_uid` | str | FK ➡️ `user.uid`, 联合唯一, 索引 | 关联的用户 ID |
| `course_node_id`| str | 联合唯一, 索引, 最大长 128 | 关联的课程 ID |
| `chapter_id` | str | 联合唯一, 索引, 最大长 64 | 关联的章节 ID |
| `status` | str | 默认 "ready", 索引, 最大长 24 | 测验状态：`generating` / `ready` / `error` |
| `questions` | JSON | 默认 [] | 生成的题目对象列表（包含题干、选项、正确答案、解析） |
| `source_outline_version` | str | 默认 "", 最大长 64 | 对应大纲的版本哈希，用于检测大纲更新 |
| `generation_error` | str | 默认 "" | 若生成失败，记录大模型或服务报错信息 |
| `created_at` | datetime| UTC | 创建时间 |
| `updated_at` | datetime| UTC | 更新时间 |

* **联合唯一约束**：`user_uid + course_node_id + chapter_id` 联合唯一。即一个用户对特定章节只保留一套测验题集（可重复生成覆盖）。

## 7. chapterquizattempt（章节测验尝试表）

记录学生每次提交试卷后的答题明细以及批改打分结果。

| 字段 | 类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |
| `attempt_id` | str | PK, 最大长 64 | 尝试记录唯一 ID；新客户端提交由用户与提交 UUID 派生稳定 ID |
| `quiz_id` | str | FK ➡️ `chapterquiz.quiz_id`, 联合索引, 最大 64 | 关联的测验 ID |
| `user_uid` | str | FK ➡️ `user.uid`, 联合索引 | 关联的用户 ID |
| `answers` | JSON | 默认 {} | 学生提交的答题键值对 (如 `{"q1": "A"}`) |
| `score` | int | 默认 0 | 测验得分 (百分制) |
| `passed` | bool | 默认 False, 索引 | 是否通关（达到合格线） |
| `grading_result`| JSON | 默认 {} | 批改报告（包含每题对错、详细反馈、薄弱知识点分析） |
| `quiz_version` | varchar(64) | 可空 | 此次提交的完整题目内容 SHA256；历史记录保持 NULL |
| `recovery_snapshot` | JSONB | 可空 | 已完成提交的薄弱点、成长概览、下一章节／课程及原始时间信息 |
| `created_at` | datetime| UTC | 提交及批改时间 |

* **联合索引**：在 `(user_uid, quiz_id)` 上建有索引，方便查询某测验的所有作答记录。

### 测验提交恢复迁移

`0005_quiz_submission_recovery` 为现有 `chapterquizattempt` 增加两个可空字段，保留全部历史数据，不回填未知题目版本。恢复快照与成绩和进度在同一事务中保存，服务端查询重放原结果。快照中的 `_attempt_created_at` 仅用于保持序列化时间一致，不作为 API 字段输出。路径替换继续沿用原删除语义。
