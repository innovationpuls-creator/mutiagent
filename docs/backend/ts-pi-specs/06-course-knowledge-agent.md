## 1. 目标范围与前置依赖

### 1.1 目标范围
在 `LangGraph.js` 主对话图中重写 **课程章节大纲节点（`course_knowledge_agent`）**，剥离旧版 1843 行代码中的历史死代码，固化“确定性大纲骨架 + Pi 中文教学命名自纠”模式，并落地 **超 8000 字教材小节自动拆节** 与 **全年多课受控并发 + 局部成功落库** 两项核心增强。

### 1.2 已锁定的业务决策
- **单小节教材正文超 8000 字**：由大纲骨架构建器**自动按段落/篇幅拆分为多个学生端小节**，不再直接报错中断。
- **全年批量生成局部失败**：已成功生成的课程正常保存落库，仅提示失败课程并支持学生单独补生成，不整批回滚。

## 2. 现有源码盘点与必须兼容的边界约束

1. **双触发模式**（`backend/app/orchestration/agents/course_knowledge.py`）
   - **单门课模式**：按指定 `course_id`（或课程名称匹配，留空则取当前学习课程）生成单门课大纲。
   - **全年多课模式**：当入参 `course_id == "__all_current_grade__"` 时，为当前学年的全部课程（4–8 门）生成大纲。
2. **教材学生可见性门禁**（`require_student_visible_textbooks`）
   - 生成前必须校验课程绑定的教材仍处于学生可见的已发布状态（非下架/归档/草稿），否则阻断生成。
3. **严格的学生端可见文案约束**
   - 学生端可见的 `title`、`description`、`key_knowledge_points` 与 `learning_sequence` 必须为自然中文教学表达，严禁直接照搬英文教材原标题，严禁泄露 `sec_1_1` 这类教材内部小节 ID。
   - 一级章节 ID 为 `"1"`、`"2"` 等正整数，二级小节 ID 为 `"1.1"`、`"1.2"`，顺序由 `order_index` 严格递增。
4. **并发防脏写契约**（`_persist_generated_outlines`）
   - 落库前必须加学生级锁（`lock_student`），对比生成前读取到的学习路径与当前数据库中的学习路径，若生成期间路径已更新则拒绝覆盖，防止脏写。
5. **与下游资源生成的衔接**
   - 若用户本轮请求直接包含“生成某门课教学内容”但该课尚未生成大纲，大纲节点完成后由 LangGraph 通过 `Command` 自动跳转至资源生成子图（M7）。

## 3. 业务模块设计与核心流转

节点内部拆为 4 个职责清晰的业务模块：

### 3.1 目标课程解析与教材上下文拉取模块
- 调 Python 内部接口获取目标课程清单（单门或当前年级全部课程）、路径版本指纹（用于落库防脏写）以及每门课绑定教材小节的元数据（`section_id`、`parent_section_id`、`title`、`content_char_count` 及正文段落边界索引），同时由 Python 侧完成教材学生可见性校验。

### 3.2 确定性大纲骨架构建器（含超 8000 字自动拆分）
- 按绑定教材小节所属章节分组，确定性生成一级章与二级小节骨架，并锁死每节的 `source_textbook_id`、`source_textbook_title`、`source_section_ids`、`source_section_titles`、`source_content_chars`。
- **超 8000 字自动按篇幅拆分规则**：
  - 当某个绑定教材小节的中文正文长度 `> 8000` 字时，骨架构建器依据 Python 返回的段落/二级标题切分点，按每段目标 `4000–7000` 字（硬上限 `8000` 字）将其均匀拆分为 2 个或多个连续的学生端二级小节（例如 `1.2` 与 `1.3`）。
  - 每个拆分出的学生端小节记录明确的来源分段范围（`source_chunk_index` / `source_chunk_total` 与字符起止偏移 `source_char_range`），确保下游 M7 小节图文生成时只读取该分段对应的正文证据，互不重叠、不超上下文预算。

### 3.3 Pi 中文教学命名与合规自纠器
- **单门课命名**：将课程目标、学生画像摘要与确定性骨架的待命名清单（含拆分分段提示，如“第 1/2 部分”）交给 Pi 结构化输出，仅生成 `personalization_summary` 与每个 `section_id` 对应的中文 `title`、`description`、`key_knowledge_points`。
- **确定性合规校验 + 1 次原地自纠**：
  - 检查：① 是否覆盖骨架中的全部 `section_id`；② 所有学生可见文案是否包含中文且非纯英文原标题照搬；③ 是否包含 `sec_*` 等教材内部编号。
  - 若不合规，将具体违规字段和原因回传 Pi 对话原地自纠 1 次；仍不通过才判定该门课大纲生成失败。
- **全年多课受控并发与逐门进度**：
  - 使用并发度限制为 `2–3` 的异步任务池并行处理多门课。
  - 每完成 1 门课，立即通过 `config.writer` 推送一条 SSE `agent_progress` 事件（如“已完成《数据结构基础》大纲（2/5）”）。

### 3.4 局部成功原子落库与收口模块
- **局部成功策略**：
  - 收集所有成功生成的大纲，逐门或成批提交给 Python 内部落库接口（带路径版本指纹，由 Python 加学生锁核验路径未变动后写入 `UserCourseKnowledgeOutline`）。
  - 若全年 5 门课中有 4 门成功、1 门失败：成功的 4 门正常落库；向学生清晰列出已生成课程清单（含引用教材及章节汇总）与失败课程名称，并提示可直接点击或回复“单独补生成《XXX》大纲”。
- **收口文案兼容**：单门成功时保持以 `"课程大纲已生成：《课程名》"` 开头并附带知识库教材引用清单，兼容前端结构化卡片挂载。

## 4. Python 内部接口契约新增

- `POST /internal/students/{user_uid}/outline-source-context`：校验教材学生可见性，返回指定课程（或当前年级全部课程）的绑定教材小节详情、路径版本指纹，以及对超 8000 字小节预计算好的安全段落切分点与字符范围。
- `POST /internal/students/{user_uid}/course-outlines/batch`：加学生锁校验路径版本指纹一致后，原子保存传入的 1 门或多门课程大纲（路径已变返回 `409`）。

---

## 5. 风险点与缓解策略

1. **拆分小节后的下游证据对齐**：拆分信息（`source_char_range`）持久化在大纲 `sections[]` 条目中，M7 小节图文生成读取教材正文时直接按该范围切片，避免重复讲同一段内容。
2. **并发触发触发个人模型限流**：全年批量生成默认并发上限锁定为 `2`（可配置至 `3`），且单门课调用均走 M2 的故障回退链，最大程度降低部分失败概率。
